# Security policy

## Reporting a vulnerability

Report suspected vulnerabilities privately through GitHub's private vulnerability
reporting feature when available. Do not open a public issue containing exploit
details, credentials, personal data, or instructions that could put users at risk.

Include the affected component, reproduction conditions, expected impact, and safe
supporting evidence. Remove or redact tokens, account identifiers, health content,
and other sensitive data before sharing.

## Scope and expectations

We prioritize authentication, authorization, account recovery, personal or
wellbeing data, encryption, deletion, moderation bypass, AI-provider boundaries,
infrastructure access, and supply-chain security.

This public document does not promise a bounty or disclose internal response
timelines. Maintainers coordinate remediation and disclosure based on severity
and user risk.
